# 浏览器验证记录：1.3.1

日期：2026-10-27（Asia/Shanghai）。

## 验证方法与边界

在真实 Chrome 的 GitHub 页面中，通过隔离的调试上下文临时运行构建产物，使用固定版本 marked 12.0.2 与 DOMPurify 3.1.6。GM 存储和菜单使用内存适配，GM 请求通过真实 fetch 访问公开 GitHub API，没有模拟 API 响应。

浏览器策略禁止自动访问扩展管理页，因此没有更新或检查油猴中的实际安装版本，也没有验证油猴权限、依赖安装、跨域请求实现及刷新后的开关持久化。不能把此结果视为完整的油猴安装端到端验证。

浏览器已有旧版 README 脚本与独立汉化脚本。Pake 切换测试前恢复了英文正文，并在测试页克隆正文和 README 入口、移除旧译文按钮及状态，隔离旧入口事件。界面翻译测试在同一次同步执行中重置真实 Settings 标签并启动新模块，读取即时结果，避免依赖旧汉化脚本的异步处理。测试改动只存在于临时标签页，不修改仓库页面或扩展配置。

## 实际结果

| 场景 | 结果 |
| --- | --- |
| `shenbourne/Pake` 默认分支 `master` | 仓库元数据、目录和 `README_CN.md` 三个 API 请求均为 200 |
| 显示中文 | 出现一个「译文」按钮，正文显示“利用 Rust 轻松构建轻量级多端桌面应用” |
| 切回 README | 状态变为 `orig`，正文 HTML 与启动前保存的英文原文完全相同 |
| 再切回译文 | 状态变为 `cn`，中文恢复 |
| 只开启界面汉化 | Settings 标签同步变为“设置”，README HTML 不变，未发起 README API 请求 |
| 只开启 README 覆盖，无独立中文文件 | 在本项目仓库验证：原正文不变，无译文按钮，汉化菜单显示关闭 |
| 缺少 `docs` 目录 | API 返回 404，被正常跳过，无脚本警告 |
| 图片修复复测 | Pake 前 9 张图片均 `complete` 且 `naturalWidth > 0` |

## 发现并修复的问题

1.3.0 直接插入外站图片会被 GitHub 的 `img-src` 安全策略拦截。浏览器安全日志确认 `gw.alipayobjects.com` Logo 被拦截；原文存在 GitHub `camo.githubusercontent.com` 代理地址。

1.3.1 使用原文图片的 `data-canonical-src` 与 `src` 建立映射，在中文文档引用相同地址时复用已有的 GitHub 代理。Pake Logo 与六个徽章恢复加载，不额外引入图片代理服务。

只出现在中文文档中、原文没有代理映射的外站图片仍可能被拦截。站内导航、其他分支与子目录、其他托管平台、私有仓库，以及 Issue/评论页面的用户内容保护尚未完成真实浏览器验证。
